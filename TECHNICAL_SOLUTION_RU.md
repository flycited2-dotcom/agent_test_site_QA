# Техническое решение: автономный QA Agent для интернет-магазина climat-simf.ru

## 1. Цель

Создать автономного QA-агента, который круглосуточно проверяет интернет-магазин https://climat-simf.ru/: доступность, каталог, карточки товаров, фильтры, поиск, корзину, формы заявок, коммуникационные ссылки, мобильную версию, SEO и технические ошибки.

## 2. Архитектурное решение

Рекомендуемый вариант размещения — VPS, а не локальный компьютер. Локальный компьютер используется только для разработки и ручной отладки. VPS обеспечивает круглосуточную работу без зависимости от включённого ПК.

Состав:

```text
VPS Ubuntu
└── Docker Compose
    └── QA Agent container
        ├── Playwright
        ├── TypeScript tests
        ├── Discovery Engine
        ├── Scenario Engine
        ├── Reporter
        ├── Telegram Notifier
        └── Scheduler loop
```

## 3. Почему Docker

Docker фиксирует окружение: Node.js, браузеры, системные библиотеки, шрифты и зависимости. Это особенно важно для Playwright, потому что браузерная автоматизация требует системных библиотек, которых обычно нет в чистом серверном окружении.

## 4. Стек

```text
Язык: TypeScript
Фреймворк: Playwright
Среда: Docker Compose
Сервер: Ubuntu 22.04/24.04
Отчёты: HTML + JSON + Markdown
Уведомления: Telegram Bot API
Хранилище: файловая структура reports/storage/test-results
Автозапуск: Docker restart unless-stopped + внутренний scheduler loop
```

## 5. Режимы работы

```text
smoke — быстрый тест доступности и базовой навигации;
critical — критический путь клиента: каталог, карточка, корзина, формы, коммуникации;
full — полный обход найденных URL и карточек;
loop — круглосуточный режим: smoke/critical/full по расписанию.
```

## 6. Сервер

Текущий сервер 2 CPU / 4 GB RAM / 50 GB SSD подходит для стартовой версии. Для полного ночного обхода большого каталога лучше временно увеличить до 4 CPU / 8 GB RAM.

## 7. Безопасность боевого сайта

Агент использует тестовые данные:

```text
Имя: QA TEST
Телефон: +79990000000
Email: qa-test@example.com
Комментарий: Автоматический тест QA Agent. Не обрабатывать как реальную заявку.
```

На стороне сайта желательно добавить распознавание тестовых заявок и их автоархивирование.

## 8. План внедрения

1. Загрузить архив на VPS.
2. Распаковать архив.
3. Запустить `install_vps.sh`.
4. Проверить `./status.sh`.
5. Открыть отчёты в `reports/`.
6. По первому отчёту добавить на сайт стабильные `data-testid`.
7. Расширить сценарии под реальную структуру магазина.
8. Включить Telegram-уведомления.
9. Перевести агента в круглосуточный режим.

## 9. Что уже реализовано в архиве

- Dockerfile на официальном образе Playwright.
- Docker Compose.
- Автоустановка Docker на Ubuntu.
- Автозапуск агента.
- Smoke-тесты.
- Critical path тест.
- Проверка форм и коммуникаций.
- Полный обход найденных URL.
- Проверка поиска/фильтров.
- SEO/tech проверка.
- Markdown-отчёт для разработчика.
- Telegram notifier.

## 10. Что нужно будет доработать после первого запуска

- Привязать сценарии к фактическим селекторам сайта.
- Добавить data-testid на ключевые элементы.
- Настроить тестовый режим заявок в backend.
- Добавить проверку API поставщиков/1С, если доступы будут предоставлены.
- Добавить AI-анализ отчётов для автоматической генерации расширенного ТЗ.
